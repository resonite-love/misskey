# 通知の統合

更新日: 2026-11-12。ぐりすぺの通常の通知欄で、れぞらぶ宛ての通知も日時順に表示する。通知ページ、通知ウィジェット、デッキの通知カラムは共通の一覧を使う。

## 利用方法と認可

設定の「GridSpace 連携」で「連携先の通知を表示する」を選び、れぞらぶの認可画面で許可する。従来の本人連携や限定投稿の閲覧許可だけでは、通知を読めない。

追加する権限は `read:gridspace-notifications` と `write:gridspace-notifications`。通知の取得と表示分の既読更新を許可する。既に許可した旧名義の返信は、追加認可でも維持する。逆向きに自動発行する認可は従来どおり限定投稿の閲覧専用とし、通知や返信の権限を付けない。れぞらぶからも通知を読みたい場合は、れぞらぶ側で追加認可する。

認可は既存の連携 ID・世代・相互認可の組に結び付ける。連携解除、追加認可の解除、元のトークン削除で利用できなくなる。新しい DB カラムや migration は追加しない。

## 表示と既読

通知の識別には受信元サーバー、受信アカウント、通知 ID を使う。両サーバーで短い ID が一致しても、別の通知として残す。受信先を各行に表示し、同じ受信先のリアクション・リノートは既存の「通知をまとめる」設定に従う。グループには全ての通知 ID を保持する。

取得だけでは既読にしない。画面内に入った通知の ID だけを、受信元へ送って既読にする。フィルターで隠れた通知、まだ取得していない通知、新しく届いた別の通知には既読を付けない。通常の Misskey の一括既読位置に加え、Redis で個別の既読 ID を管理する。通常の未読件数、通知ストリーム、遅延して届く未読イベントもこの状態を使う。

未読バッジは両サーバーの件数を合計する。相手の件数を取得できない場合は `?` を表示し、0 件とは扱わない。追加認可をしていないアカウントでは、従来の通知一覧を使う。

## 投稿の内容と操作

れぞらぶの通知に含まれる投稿は、旧アカウントの現在の閲覧権限で確認する。宛先限定や「連合なし」の投稿、CW、添付画像も対象とする。取得側でもブロック・ミュートを確認する。本文を通常の投稿キャッシュへ保存せず、添付は既存の認可付き取得経路で読む。

通知一覧を表示している間は、約10秒ごとに新着取得と表示済み内容の再確認を行う。相手側の通信失敗、投稿削除、権限失効を確認したら該当内容を取り除く。ページを隠したときや離れたときも、相手側の本文と読み込んだ画像を破棄する。片側が取得できなくても、もう片側の通知は利用できる。

投稿には既存の旧名義返信の操作を使う。フォロー申請の承認など、まだ代理操作を実装していない通知には「受信先で開く」を表示する。外部サーバーへ通知を複製・配送しない。

## API と更新方法

本人の Web セッション用 API は `gridspace/notifications` と `gridspace/notifications/read`。`source` で自分側と連携先を選び、サーバー間は固定した相手への署名付き `/gridspace/v1/notifications/query`・`read` を使う。API 入力から送信する条件を選び、ログイン用トークンや任意の追加フィールドを相手へ転送しない。応答には `Cache-Control: no-store` を付ける。

既存の `i/notifications`・`i/notifications-grouped` の形と既定動作は変更しない。通常の通知ストリームに個別既読後の件数を知らせる `notificationRead` を追加した。

相手側の通知は10秒間隔、未読バッジは15秒間隔の問い合わせで更新する。自分側の新着は従来のストリームを使い、ポーリング設定時にはストリームを開かない。再取得では続きのページも読み、接続が切れている間の新着を補う。OS のプッシュ通知と、相手側からの即時ストリーム配信は今回の範囲に含めない。

## 確認方法

`scripts/gridspace/test-notifications.mjs` は、専用の G/R 環境で認可、85件ずつのページ送り、取得時の未読維持、表示分だけの既読、取得後の新着、限定投稿の削除、連携解除を確認する。Redis の実処理で、既読位置と個別既読の共存、同時到着、64bit の通知順序も確認する。

`scripts/gridspace/test-notifications-ui.mjs` は、Chrome で実際の認可画面、混在表示、添付画像、更新、解除、通信失敗後の再試行を確認する。認証情報と画像は `.config/` に保存し、Git 管理から除外する。グループがページ追加で大きくなる場合の表示と既読は、応答を固定した画面試験で補う。
