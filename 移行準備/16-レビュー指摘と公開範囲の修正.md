# レビュー指摘と公開範囲の修正

2026-11-12、Claude Code の総合レビューで挙がった公開範囲の問題を優先して修正した。対象は、履歴と本文の共有、投稿者の公開設定の反映、未ログイン時のローカルタイムラインである。レビューの全指摘への対応完了を意味するものではない。

## 修正した動作

- 時間指定で非表示・フォロワー限定になった投稿は、共有用の履歴と本文取得では渡さない。履歴と検索は同じ判定を使い、本文だけでなく投稿 ID の候補からも除外する。旧アカウントの権限で読む経路は引き続き利用できる。
- ログイン必須の投稿は、未ログインの履歴に出さない。ログイン中の利用者は従来どおり読める。
- 相手サーバーの投稿者情報を初めて取得するときと更新するときに、Misskey が送る `_misskey_` 付きの公開設定を読み取る。相手側にフォロワーがいない投稿者の設定変更も、固定した連携先へ ActivityPub の Update として配送する。
- すでに共有済みの投稿が後からフォロワー限定になっても、通常のフォローで読める利用者にはプロフィール履歴を表示する。匿名の閲覧者には出さない。
- 投稿が存在するものの共有できない場合は、本文を含まない `unavailable` 応答を返す。削除を表す `deleted` と区別し、取得の拒否だけでは削除記録を作らない。実際に削除された投稿には従来どおり削除記録を残す。
- 未ログイン時の LTL は、データベースから取得する場合と Redis から取得する場合で同じ公開設定に従う。「ローカルのみ」の設定なら、連携先の投稿は含めない。

## 更新時の注意

両フォークを同時に更新する。旧版は `unavailable` 応答を解釈できず、取得を失敗として扱う。

既存の投稿者情報は、コードの更新だけでは書き換わらない。更新時には連携先の投稿者について `federation/update-remote-user` で再取得する。今回のテスト環境では、両側の保存値を送信元と比較し、不一致だった G の1件を再取得して一致を確認した。R に不一致はなかった。

今後の設定変更は通常の ActivityPub 配送キューを使うため、相手側への反映には配送待ちの時間がある。相手サーバーの停止中まで即時反映される仕組みではない。

修正前に作られた削除記録は自動では消さない。過去の誤記録を修復する場合は、送信元に投稿が現存することを個別に確認する。本当に削除された投稿の復活を避けるため、削除記録の一括消去は行わない。
