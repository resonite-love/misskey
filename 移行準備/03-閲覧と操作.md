# 03 閲覧と操作

状態: R-05〜R-09、R-11、R-13〜R-17 の実装設計案。表示の統合と、元の投稿に対する権限を別々に判定する。

## 一覧の区別

| 一覧 | 取得するもの |
| --- | --- |
| コミュニティ TL | 両サイトのパブリック投稿。ローカル指定も含め、既存 LTL 相当の返信・Renote フィルターを適用する |
| 本人のホーム TL | 開いているサイトの現在の購読対象。旧側の取得結果もこの条件で絞る |
| メンバーのプロフィール | 紐づいた新旧アカウントの履歴のうち、閲覧者が読める投稿 |
| 検索 | 両側へ同じ条件で問い合わせた、閲覧可能な検索結果 |

コミュニティ TL は新旧アカウントを持つ人だけでなく、どちらか一方だけのメンバーの公開投稿も含む。相手の登録や個別 Follow を条件にしない。表示名を揃えても元の Actor URI を改変しない。

## 公開範囲ごとの判定

| 元の指定 | コミュニティ TL | 連携した本人のホーム・履歴・検索 |
| --- | --- | --- |
| パブリック | 対象。ブロック等の制限は優先する | 各一覧の条件に従って対象にする |
| ホーム | 全員向けには流さない | 旧新の購読に基づきホームへ表示する。履歴・検索は元の公開範囲に従う |
| フォロワー限定 | 対象外 | 新側の承認済み権限、または本人の旧権限で読める場合だけ表示する |
| 指名・ダイレクト指定のノート | 対象外 | 宛先となったアカウントの権限でのみ表示する |
| ローカルのみ・連合なし | 元がパブリックなら両サイトの共通 LTL に含める。外部へは配送しない | 元の公開範囲を守り、両サイトの共通ローカル範囲で取得する |

「ローカルのみ」は連合配送を止める設定であり、常に「ログインした人だけが読める」という意味ではない。[公式の公開範囲説明](https://misskey-hub.net/ja/docs/for-users/features/note/)

今回のフォークではこの配送範囲を二つのサイトへ拡張する。共通ローカル用の経路で配送し、一般の ActivityPub 配送や外部リレーには載せない。ホーム＋ローカルは購読者向け、フォロワー限定＋ローカルは承認済み閲覧者向けのままにする。新着は同時更新後から、更新前の投稿は履歴の検索・スクロールで取得する。履歴取得を理由に新着通知を発行しない。

限定投稿は、取得元サーバーがその閲覧者の旧アカウントで現在読めると判定した結果を使う。運営の権限で読んだものを本人のデータとして返さない。引用元、返信元、添付、リアクションの明細にも同じ判定を適用する。

## 識別とページ送り

ノートは元の ActivityPub Object URI で識別し、通常のローカル ID は `サーバー + ID` で扱う。二つのサーバーの短い ID を同じ名前空間に入れない。本文・時刻が同じというだけでは重複と判定しない。

新旧の取得元と連合経由で、同じ URI のノートが届いた場合は一件にまとめる。Renote は元ノートと別の行為なので、元の投稿と一緒に消さない。

時刻で統合して並べ、同時刻は元 URI などの安定したキーで順番を決める。ページ送りのカーソルには各取得元の進捗と未表示分を持たせる。片方の `untilId` をもう片方へ使わない。検索語、閲覧者、連携の世代が変わればカーソルを作り直す。

途中で片方が停止した場合は、取得できた側を表示し、未取得の側と理由を示す。「結果なし」や「検索完了」とは表示しない。

## プロフィールと検索

代表表示、旧新のアカウント、連携が確認された状態、投稿元を表示する。旧ユーザー名による検索でも同じメンバーにたどり着ける。連携していない同名の人は統合しない。解除後の検索結果の扱いは Q-06 に従う。

人を指定した投稿検索は紐づいた Actor の集合へ展開する。旧側の未取得の過去投稿も検索するため、ぐりすぺに保存済みの投稿だけで検索を完結させない。

検索エンジンごとに対応範囲が違う。確認した Meilisearch の登録対象はパブリックとホームであり、フォロワー限定を含む検索を当然に提供できるとは扱わない。初回公開で約束する検索範囲と採用エンジンは Q-05 で決める。本文を表示する直前にも権限を確認し、索引の件数や抜粋から限定投稿を漏らさない。

## 投稿・返信・リアクション

新規投稿の既定は現在開いているサイトの本人のアカウントとする案。送信前に名義と公開範囲を表示する。投稿元を途中で自動変更しない。

通常の返信・リアクションは操作するアカウントで元のノートへ送る。R-15 により、新アカウントが参加できない会話には旧名義で返信できるようにする。旧名義を明示し、要求ごとに旧側で閲覧・書き込み権限を確認する。元の宛先や公開範囲を広げない。旧名義の利用許可がない場合は再認可を求め、勝手に新名義へ切り替えない。

共通ローカル投稿への返信・引用・Renote には、外部へ配送しない制約を引き継ぐ。公開範囲を変える操作で原文や添付が外部へ配送されないようにする。

二重送信を防ぐ操作 ID を付ける。送信後に通信が切れて結果が分からない場合は、確認してから再送する。異なる Actor で同じ操作を送り直さない。

投稿の削除・編集・投票・通報は対応する元サーバーの操作へ送る。編集等の対応可否は採用版ごとに確認する。通報は対象を管理できる運営へ届く経路を用意する。

画像・動画、CW、カスタム絵文字、投票、返信ツリーを元の意味で表示する。旧ドライブを新しい所有者へ一括移転することは、この表示統合の前提にしない。限定添付の URL は公開キャッシュへ保存しない。

## 通知と既読

通知は `取得元 + 受信アカウント + 通知 ID` で識別する。片方の通知 ID だけで重複判定しない。同じ投稿に対する別アカウント宛ての通知は、受信先を失わない形でまとめる。

裏で通知を取得するときは `markAsRead: false` を指定する。現在の既存 API は既定で全件既読を実行するため、取得だけで旧通知を既読にしない。画面での既読操作は各取得元へ送る。一部通知だけを表示したのに他の通知まで既読にする API しかない場合は、拡張か明示的な「すべて既読」が必要。

リアルタイム接続は両方を購読し、切断後は履歴 API で取りこぼしを補完する。片方の停止で新側の通知まで停止しない。未読数は未取得をゼロと扱わない。

閉じたアプリへのプッシュ通知は Q-08。画面内通知をまとめることと、OS へ送るプッシュ通知をまとめることは別の受け入れ条件とする。
