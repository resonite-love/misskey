# 14 連携先の自動フォロー

更新日: 2026-11-12。ぐりすぺで旧アカウントをフォローしている相手が、あとからぐりすぺへ連携した場合も、新アカウントを自動でフォローする。すでに連携済みの相手や、初回コピー済みの利用者も対象にする。

## 利用者から見える動作

A さんがぐりすぺへ連携すると、れぞらぶでのフォローを一度だけコピーする。その後 B さんがぐりすぺへ連携したとき、A さんがぐりすぺで B さんの旧アカウントをフォロー・申請中なら、B さんの新アカウントも追加する。B さんが先に連携していた場合も同じように追加する。ブラウザを開いておく必要はない。

- 旧アカウントへのフォローは残す。新旧の投稿者 ID は統合しない。
- 新アカウントが鍵付きなら、通常のフォロー申請になる。旧アカウントでの承認は流用しない。
- 旧アカウントへの申請が承認待ちでも、新アカウントへのフォローは通常の手順で進める。
- 新側で旧アカウントをフォロー解除・申請取消したら、その相手の新アカウントは追加しない。追加済みの新アカウントは自動解除しない。
- 新アカウントへのフォローを解除・申請取消した場合や、相手に却下された場合は、自動で復活させない。必要なら手動でフォローする。
- 新側で旧・新どちらかをミュート・ブロック中の場合や、相手からブロックされている場合は省略する。省略後に制限を解除しても、自動で追加し直さない。
- 停止・削除・引っ越し済みのアカウントも省略する。
- 連携解除で今後の自動追加は止まる。追加済みのフォローは残る。

判定に使うのは、ぐりすぺの現在のフォロー・申請である。コピー後にれぞらぶだけで追加・解除した関係は同期しない。ぐりすぺで手動追加した旧アカウントも、上の条件を満たせば対象になる。既存の新アカウントへのフォロー設定は上書きせず、新規追加時だけ旧アカウント側の「返信を含める」を引き継ぐ。

## 実装と再試行

`GridspaceFollowExpansionService` が3秒間隔で確認し、1回につき最大20組を処理する。混雑時は反映まで時間がかかる。対象者の組を順に走査するので、失敗した組だけが後続を止めることはない。

ぐりすぺ側では、本人と相手の両方がこのサーバーから固定された連携先へ OAuth 連携している組を対象にする。外部サーバーの同名アカウントやプロフィールの文字列からは連携を推測しない。ActivityPub の配送方式は変更しない。

追加前に両者の有効な連携、世代、認可をサーバー間で確認する。本人・相手の連携変更と本人の解除操作は、同じロックで順序を揃える。フォロー自体には通常の `UserFollowingService.follow` を使い、承認、通知、ホーム配信のキャッシュ更新を通す。

新しい `gridspace_follow_expansion` テーブルへ、フォローする本人と新アカウントの組ごとに処理結果を保存する。通信・DB 障害後は処理待ちから再試行し、完了済み・省略済みは再実行しない。再試行の間隔は最大5分まで延ばす。送信後に結果の保存に失敗しても、既存のフォロー・申請を確認する。手動解除・却下の記録は連携を作り直しても残し、復活を防ぐ。

自動追加の結果は管理用テーブルに保存する。設定画面の「コピー進捗」は引き続き初回コピーの件数であり、この追加分は含まない。既存の Misskey API にパラメーターやレスポンス項目は追加していない。

## 導入と検証

両フォークに新しい migration を適用してから、更新したサーバーを起動する。旧版からの既存の連携も定期走査の対象になるため、再連携は不要。migration の `down` は追加テーブルを削除するが、作成済みの通常フォローは削除しない。

検証コマンドは `scripts/gridspace/README.md`、実行結果は [10-実装状況](10-実装状況.md) に記録する。

CHANGELOG 候補: 連携した相手の新アカウントを自動フォローし、あとからの連携にも対応しました。

## れぞらぶ側の自動フォロー（.23）

れぞらぶで旧アカウントをフォローしている人も、連携先のぐりすぺアカウントを自動でフォローする。フォローする本人のアカウント連携は不要で、移行していない人も対象になる。旧アカウントへのフォローは残す。

すでに連携済みの相手と、今後連携する相手の両方を定期的に確認する。対象にするのは成立済みの旧フォローで、旧アカウントへの承認待ちの申請は含めない。新アカウントが鍵付きなら、通常のフォロー申請を送る。

旧・新アカウントのどちらかをミュート・ブロックしている場合は追加しない。停止・削除・引っ越し済みのアカウントも除外する。新アカウントを手動でフォロー解除した場合や、申請を取り消した・却下された場合は復活させない。

相手の連携は、既存の署名付き履歴APIに件数0で照会して確認する。この確認では投稿を取得せず、フォローする本人のOAuthトークンも使わない。連携解除後は追加を止める。通信障害は処理待ちとして再試行し、アカウントの解決に失敗したときは1分待ってから試す。

1回の処理は最大20組で、通常のフォロー処理を使う。既存の処理記録と手動解除の記録を再利用し、完了した組は繰り返さない。新しいデータベースのテーブルや列は追加しない。

検証では、未連携のれぞらぶユーザーによる自動フォロー、旧フォローの維持、ミュート、手動解除、鍵付きアカウントの承認待ちを確認する。実行スクリプトは `scripts/gridspace/test-source-follow-expansion.mjs`。
