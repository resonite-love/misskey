## 実装方針としての提案

| ID | 提案 | 理由 |
| --- | --- | --- |
| P-01 | D-10 の基盤で同じフォークをサイト別設定にして配備する | 作業先の基準ブランチは揃えた。本番の配備と更新手順は未確定 |
| P-02 | 元の Actor URI と Object URI を保持する | 外部の返信先と投稿者を維持し、二重投稿を避ける |
| P-03 | 旧権限で読める投稿を取得し、G の現在の購読条件で絞る | コピー後の Follow の独立と、従来の閲覧継続を両立する |
| P-04 | 共通ローカルは専用の配送制約を持たせる | 外部リレーや引用による再配送を防ぐ |
| P-05 | 投稿元のデータを原本とし、過去履歴は問い合わせで補完する | 全履歴の移植を利用開始の条件にせず、削除や権限変更を反映する |
| P-06 | 既読を伴わない通知取得と、確認可能な操作 ID を用意する | 勝手な既読と二重投稿を防ぐ |

提案は、利用者が具体的な実装方法まで承認した記録ではない。採用するものを設計レビューで決める。

## 過去の説明の修正

旧ホーム TL と新ホーム TL を無条件に結合するだけでは、D-05 を満たさない。新側で解除した人の投稿が旧側から戻るため、新側の現在の購読条件で絞る。

ローカルのみを共有しない案は D-06 により変更した。共有範囲は二つのサイトまでとし、外部配送禁止を維持する。過去投稿も D-07 の対象だが、フォロワー限定・指名の閲覧権限を拡張する決定ではない。

以前参照したリレー TL は、初回の作業先の 2023 年版には存在しなかった。D-10 の切り替え後は作業先にも含まれる。ただし、共通ローカルや本人連携の要件をそのまま満たす機能とは扱わない。
