# 06 受け入れ条件

状態: 実装前の検証計画。以下の表は未実行であり、合格記録ではない。

## 検証用の人物と環境

R はれぞらぶ役、G はぐりすぺ役、E は通常の外部サーバー役とする。実サービスの本番ドメインでは実験しない。

kokoa は R/G を連携する本人。A は R だけの投稿者、B は R/G を連携した投稿者、C は G だけの新規利用者、D は鍵アカウント、X は外部の投稿者とする。同名の別人、ブロック済み、認可取消済みのケースも作る。

## 実装時の試験方法

条件分岐とデータ変換は最も近い単体試験、認可・履歴・フォローは API 試験、配送禁止・外部からの見え方は複数サーバーの連合試験で確認する。画面では名義、既読、部分失敗、ページ送り、モバイル表示を確認する。

現在の checkout には [OAuth 試験](../packages/backend/test/e2e/oauth.ts)、[TL 試験](../packages/backend/test/e2e/timelines.ts)、[公開範囲試験](../packages/backend/test/e2e/api-visibility.ts)、[連合の公開範囲試験](../packages/backend/test/e2e/ff-visibility.ts) がある。基盤更新後に配置と実行コマンドを再確認する。

実行記録には対象コミット、環境、ケース ID、結果、確認できなかった点を残す。今回のドキュメント検査はこれらの機能試験の代わりにはならない。
