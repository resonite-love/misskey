# ユーザー指定検索とチャンネル表示の修正

2026年11月13日。対象リリースは両フォークの `2026.11.0-*.11`。

## 原因と変更

ぐりすぺで自分を選び `a` を検索すると、通常検索は `peerAvailable: false`、限定検索は `GRIDSPACE_PRIVATE_UNAVAILABLE / PEER_UNAVAILABLE` を返した。同時刻のれぞらぶには PostgreSQL の statement timeout があった。

著者指定でも大量の本文一致行を対象にする計画と、TypeORM の結合付き `take()` が作る DISTINCT・ソートが負荷を増やしていた。取得対象の結合は to-one なので、SQL の LIMIT で必要件数を先に制限する。著者指定時だけ本文/CWを著者索引から絞り、トランザクション内の bitmap scan を無効にする。全体検索の索引経路と3秒のDBタイムアウトは維持する。

限定検索では著者IDと過去投稿の公開範囲設定を先に解決する。候補の絞り込み後も、本文を返す前には現在の完全な権限条件で再確認する。設定変更と重なると一時的に結果が欠ける場合はあるが、この最適化で閲覧範囲を広げない。

## 表示部品の共通化

- 連携ノートのヘッダーは通常の `MkNoteHeader` を使用する。
- リアクションは通常の `MkReactionsViewer` と参加者tooltipを使用する。アバター、追加・取消の確認、絵文字ピッカーを表示し、操作先は連携アカウントのAPIに切り替える。
- 参加者プレビューは認可済みのノート応答に含める。ボタンごとの定期API呼び出しをなくし、hoverまたは一覧を開く操作で詳しい参加者一覧を取得する。
- プレビューは各サーバー最大20件、統合後も最大20件に制限する。取得元ごとのリアクション所有関係を使い、ActivityPubで複製された主リアクションを二重に扱わない。サーバー内ではノートごとのDB問い合わせが追加される。
- チャンネルを開く際の専用センシティブ確認ボタンを除去する。CWとセンシティブ添付の閲覧操作は残す。
- タブ非表示・画面破棄時に連携tooltipと参加者表示を破棄する。操作中の名義変更を検出し、別名義で続行しない。

相手サーバーのIDをローカルのノートIDとして登録したり、通常の書き込みAPIへ渡したりしない。認可付き本文・ファイルの破棄処理を維持する。

## 残っている統一作業

このリリースは[25番の全項目](25-通常UIと連携UIの統一.md)の完了ではない。ノート全体は引き続き `MkGridspacePrivateNote` が組み立てる。通知カードと操作、チャンネル以外の返信・投票・CW、メディアビューア、メニュー、チャンネル管理、一覧の復帰と新着アニメーションは別途統一する。

## 検証

- 本番DBの読み取り限定調査で、著者指定 `a` / `A` の通常・限定検索と次ページが3秒以内に収まることを確認した。これは調査時点の条件であり、任意の語句や著者の速度保証ではない。
- PASS: APIテストで著者指定、CW、ページ送り、絶対・相対の過去投稿公開範囲、認可解除、ブロック、添付を確認した。
- PASS: ブラウザテストで両サーバーの検索と、チャンネル投稿・返信・投票・アバター・tooltip・認可解除を確認した。閲覧中のボタン単位のreaction-list呼び出しは0件、hover時だけ1件だった。
- PASS: 第三のサーバーを使い、通常のActivityPubで投稿・主リアクションを受信すること、特別な複数リアクションを外部に送らないこと、外部投稿を通常経路で取得することを確認した。
- PASS: APIの追加フィールドに合わせて `misskey-js` を再生成した。DB migration はない。
- BASELINE: リポジトリ全体のfrontend型検査には既存エラーがある。今回の変更ファイルに新しい型エラーはなかった。

デプロイ時のイメージdigest・revision・検証結果は、ローカルの `MisskeyDeployments/20261113-parity11` に記録する。
