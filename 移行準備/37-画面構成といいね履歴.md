# 画面構成の引き継ぎと、いいね履歴の共有

更新日: 2026-11-14。対象: 両フォークの `2026.11.0-*.31`。

## 利用者から見た動作

新しい連携時の設定取り込みと、設定画面の「れぞらぶの設定に揃える」で、次を引き継ぐ。

- 既定のアップロード先。ファイルをコピーせず、共有ドライブ内の同じフォルダーに対応付ける。
- デッキのプロファイル、選択中のプロファイル、列の順序・幅・重ね方、壁紙。
- ウィジェットの配置と設定、メモの内容。
- 列やウィジェットが参照するリスト・アンテナ・クリップ・チャンネル。リストは既存の初回コピー先を使い、その他は共有元を参照する。

取り込み後は開いているデッキにも反映する。デッキ未使用のアカウントから取り込んだ場合も、空の Main プロファイルを作り、後から追加した列を保存できる。

参照先が削除済みなどで解決できない場合は、別の同名・同IDのデータに置き換えない。アップロード先は変更せず、列・ウィジェットは案内を表示し、設定し直せるようにする。サーバー固有のロールタイムラインは設定し直す必要がある。

プラグインは引き継がない。ウィジェット内の AiScript App はコードを保持するが、取り込み先で「引き継いだスクリプトを実行する」を押すまで実行しない。ドライブのファイルを指定した全体の通知音と、リスト指定の通知受信設定は、従来どおり対象外。

## ページ・ギャラリーのいいね

通常の「いいねしたページ」「いいねしたギャラリー」に、連携先の履歴も日時順で表示する。元のいいねを参照するので、取り込みによって件数が増えることはない。

連携先の作品を開いた画面から、連携先アカウントのいいねを追加・解除できる。再試行で同じいいねを重複させない。両方向で利用でき、未連携の利用者には通常のローカル履歴だけを表示する。

取得時に連携先アカウントの閲覧範囲、ブロック、投稿者の状態を確認する。ページの限定公開範囲も確認する。一覧は表示中に再確認し、非表示・画面離脱・認可失効・取得失敗時には共有分を消す。再確認は重複起動せず、画面を離れた場合は中断する。

## 技術上の範囲

- OAuth の設定スナップショットを拡張。認証情報・プラグインは対象外。
- `gridspace/layout-reference` は認証済みの固定ペアに限定し、共有ドライブの所有者・コピー済みリストの所有者を確認する。
- `gridspace/managed-resource` に履歴取得、閲覧、いいね追加・解除を追加。書き込み直前と応答直前にも連携状態を確認する。
- 通常の Misskey API の変更は、いいね一覧の日時を表す任意フィールドなどの追加のみ。他サーバー向けの ActivityPub は変更しない。
- DBスキーマの変更はない。

## 検証

- Backend: 参照先の所有者確認・認可取消・不正入力、いいねの閲覧範囲とページ送り、既存クリップ・共有ドライブの近接テスト。
- Frontend: 配置と参照IDの変換、不正な配置の拒否、実行待ちのスクリプト、開いているデッキへの反映、空プロファイルからの保存。
- 両サーバーの試験: `scripts/gridspace/test-layout-likes.mjs`。OAuth設定の受け渡し、共有フォルダー、リスト対応付け、両方向のいいね、重複再試行、ブロック、未連携時を確認する。
