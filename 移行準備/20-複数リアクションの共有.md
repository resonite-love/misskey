# 複数リアクションの共有

更新日: 2026-11-12

## 対応範囲

れぞらぶ・ぐりすぺ間で、公開・ホーム公開の投稿に付いた複数リアクションを表示する。「連合しない」共有投稿と、通常連合で届くフォロワー限定・指名投稿も対象とする。件数、自分が付けた種類、リアクションした人の一覧を取得でき、種類ごとに追加・取消できる。一人が一つの投稿に付けられる上限は従来どおり16種類。

通常の投稿には操作中のサーバーのアカウントで反応する。旧アカウントの権限で読む限定投稿には、操作の追加認可を受けた旧アカウントで反応する。限定投稿の一覧閲覧だけでは追加・取消の権限は付かない。

## API と保存先

通常投稿には既存の `notes/extended-reactions/create`・`delete`・`show`・`list` を使う。`show` には共有対象かを示す `shared`、両サーバーの取得が揃ったかを示す `complete`、集合の変更を判定する `revision` を加えた。`list` のページ送りには返された行の `id` をそのまま渡す。

通常の Note レスポンスには `gridspaceReactions` を追加し、相手側の限定投稿でも拡張 API を選べるようにした。この項目は LTL 共有用の `gridspaceShared` とは別で、投稿の公開範囲を広げない。チャンネル投稿は相手サーバーとのリアクション共有の対象外とする。

限定投稿には既存の `gridspace/private-action` を使い、`add-reaction`・`remove-reaction`・`reaction-list` を追加した。追加・取消を再送しても、付いている状態と外れている状態が反転しない。

追加分の保存先は反応したアカウントの所属サーバーとする。両サーバーは署名付きの `/gridspace/v1/reactions` で一覧を取得し、通常の ActivityPub でも届く最初のリアクションを二重に数えない。カスタム絵文字は所属サーバーを含めて区別するため、同名でも混同しない。

投稿の所属サーバーが閲覧者の権限を確認する。相手側にあるキャッシュからは、自サーバーの利用者が付けた分だけを、署名で確認した元の所属サーバーへ返す。元のサーバー内のフォロー関係をキャッシュ側へ複製する必要はない。

## 更新と障害時の動作

表示中の共有投稿は約10秒間隔でまとめて取得する。タブが非表示の間は定期取得を止める。同じ件数でも反応した人が入れ替われば一覧を更新し、集合が変わらなければ人の一覧を取り直さない。

相手サーバーに接続できない間は、最後に取得した共有集計を画面に残す。自サーバーへの操作が成功した場合、自分の選択状態は更新する。相手側の投稿への追加・取消は取得元への接続に失敗すると `PEER_UNAVAILABLE` で失敗する。

反応した人の一覧は相手サーバーや未取得の外部アカウントを解決できない場合に再試行可能なエラーを返す。取得できない人を飛ばして、ページの終わりに見せる処理はしない。

## 外部との互換性と残る制約

特別な通信は設定した2サーバー間だけで使う。通常の `notes/reactions/*` と外部向け ActivityPub の動作は維持する。外部には最初のリアクションだけが通常の連合で届き、追加分は送らない。「連合しない」投稿は外部へ送らない。

今回の対応は表示・追加・取消・反応者一覧まで。相手サーバーの投稿に付けた2種類目以降を、投稿者への新しい通知として直接届ける処理は未実装。同じサーバー内や旧アカウント名義での追加には、既存の通知処理を使う。

両フォークの更新が必要。片側だけが古い間は共有集計が揃わず、相手側の投稿への拡張操作は失敗する。既存のマイグレーションへの変更や新しいテーブルの追加はない。大量の投稿・利用者を想定した負荷試験は未実施。

## 検証

- `scripts/gridspace/test-reactions.mjs`: G/R 双方向の公開・ホーム・連合なし・フォロワー限定・指名投稿、追加・個別取消、反応者のページ送り、同名カスタム絵文字、旧形式のリアクション、ブロック、外部の通常連合を確認。
- `scripts/gridspace/test-actions.mjs`: 旧名義の複数リアクション、再送、最初の反応だけの取消、反応者一覧、限定投稿の権限を確認。旧Rアカウントだけが読めるGの指名投稿も含む。
- `scripts/gridspace/test-reactions-ui.mjs`: ブラウザーでの表示・操作、相手サーバーを停止した間の動作と復旧、限定投稿の操作を確認する再現試験。
- バックエンドの単体テスト: 署名・再送拒否、入力制限、ソース側の拒否、通信失敗、認可失効を確認。
- フロントエンドの単体テスト: 対象投稿の判定、取得の集約、タブ非表示中の停止、購読終了時のタイマー解除を確認。

変更履歴候補: れぞらぶ・ぐりすぺ間で複数リアクションの表示・追加・個別取消に対応。
