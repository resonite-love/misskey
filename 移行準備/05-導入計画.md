# 05 導入計画

状態: 実行前の計画。日付、担当者、本番環境の構成は未確定。実施済みの作業を表すものではない。

## 採用した基盤で配備を準備する

作業先は `resonite-love/misskey` の `resonite-master` に切り替え、`2026.10.0-resonite-love.6` を基準とした。[現行実装調査](08-現行実装調査.md) の記録を起点に、本番のれぞらぶのバージョン、独自変更、データ量、検索エンジン、添付ストレージ、バックアップと復旧方法を確認する。認証情報や本番データはこのフォルダへ貼らない。

両サイトをこの基盤と互換性のある連携版に揃える。基盤の更新と連携機能は別々に検証できる変更にし、更新前のデータでアップグレードと復旧を試す。ローカルの作業ブランチは切り替え済み。本番の更新、連携機能の実装、配備はまだ行っていない。

## 実装の依存関係

変更箇所、試験、完了条件を含む作業単位は [09-実装計画](09-実装計画.md) にまとめた。以下は導入に向けた大まかな段階であり、具体的な着手順は実装計画の T00〜T14 に従う。

| 段階 | 完了条件 |
| --- | --- |
| 基盤と連携仕様 | 採用ブランチと本番の差分を確認し、連携プロトコルのバージョン、検索範囲、未決事項を決める |
| アカウント連携 | OAuth、重複防止、解除、認可の取消を単独で確認する |
| フォロー取り込み | 一回だけのコピー、承認待ち、部分失敗、新側の独立した Follow を確認する |
| 本人の閲覧 | 新側の購読条件で旧側の投稿を表示する。履歴、検索、通知を統合する |
| 共通ローカル | 新着配送、開始位置、外部配送禁止、削除、履歴補完を確認する |
| 操作 | 旧名義の返信、二重送信防止、通知の既読、失敗時の表示を確認する |
| 本番導入 | 外部サーバーを含む受け入れ確認と切り戻し訓練を完了する |

各段階を小さな変更としてレビューし、最も近いテストを選ぶ。共通ローカルの配送禁止は UI だけでなく、ActivityPub の配送、リレー、引用、添付、プッシュの各経路で確認する。

## 試験環境

本番とは別のドメインで、れぞらぶ役、ぐりすぺ役、通常の外部サーバー役を用意する。テスト用アカウントで、連携済み、未連携、片方だけ、鍵、ミュート、ブロック、指名投稿、連合なしを再現する。

本番のアカウント鍵やトークンを持ち込まない。本番データが必要な負荷検証は、利用範囲と匿名化を決めてから実施する。負荷確認では初回 Follow、履歴検索、全体 TL、再接続時の補完を別々に計測する。

## 同時更新と共有開始

R-16 に従い、両サイトの更新を一つの作業計画にする。ただし短時間のバージョンの違いは起こるため、両側の準備が整うまで連携機能を有効にしない。

1. バックアップと復元可能性を確認し、更新と共有範囲の変更を告知する。
2. 両側に同じ連携版を配備し、機能を無効にした状態で通常利用を確認する。
3. 相互認証、対応操作、共有ルールを確認し、共有開始日時とイベント位置を確定する。
4. 運営の試験用アカウントで連携・フォロー・旧名義返信・解除を確認する。
5. 新着共有を有効にし、段階的に連携受付を開く。
6. 過去の投稿は検索・スクロールで取得する。履歴を新着として全件配信しない。

告知では外部からは別アカウントであること、Follow は最初だけコピーされること、ローカルの範囲が両サイトになること、過去投稿も参照できること、旧名義の操作を説明する。文案は別途レビューする。

## 観測するもの

連携の成功・失敗・再認可、取り込み対象と承認待ち、新着配送の遅延、補完待ち、重複イベント、削除の未反映、検索の片側失敗、名義別の操作結果を集計する。トークン、限定投稿本文、個別の検索語を通常の運用ログへ出さない。

公開初期は例外だけでなく「片側が取得できず結果が欠けている」状態も監視する。監視の閾値、通知先、運営担当は Q-10。全体の停止と利用者一人の再認可を区別する。

## 切り戻し

入口の停止、新規連携の停止、共通ローカル配送の停止、本人としての代理操作の停止を別々に制御できるようにする。問題の機能だけを止めても、各サイトの元のアカウントで利用できることを確認する。

フォローの初回コピーを戻す場合は、取り込み後に利用者が変更した関係を上書きしない。旧名義で作成済みの投稿を自動削除しない。連携を止めてもノートの外部配送禁止は維持する。

データベース変更がある場合、古いコードを起動すれば戻せるとは扱わない。移行前後のスキーマ互換性と復元手順を別に用意する。ローカル投稿が誤って外部へ配送された場合、受信済みコピーを完全に回収できるとは約束しない。

## 利用を移していく期間

れぞらぶの終了期限は決めない。旧ドメイン、過去の投稿 URL、旧権限がどの程度使われているかを観測し、維持する機能を後から判断する。全員が新アカウントを作ったことだけで、旧側のデータとサーバーが不要になったとは判断しない。
