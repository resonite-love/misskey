# 13 旧名義での操作と登録案内

更新日: 2026-11-12。両フォークの試験環境で、旧名義によるリアクション・投票・添付付き返信、限定投稿の MFM とカスタム絵文字、新規登録後の連携案内を実装した。

## 利用手順

設定の「アカウント連携」で「リアクション・投票・添付を許可する」を選び、連携先の OAuth 画面で許可する。既存の閲覧・返信・通知の許可は引き継ぐ。逆方向に自動で発行する許可は、引き続き閲覧専用とする。

限定投稿の「リアクション・投票」を開くと、操作する旧アカウントが表示される。リアクションは一覧の絵文字、Unicode 絵文字の入力、または連携先の `:絵文字名:` で指定できる。自分のリアクションは取り消せる。投票は単一選択・複数選択に対応し、投票済みの項目や終了した投票には追加で投票できない。

返信フォームではファイルを選び、説明とセンシティブ指定を付けられる。本文なしの添付だけの返信もできる。ファイルは旧アカウントのドライブへ保存し、そのアカウントの名義で返信する。宛先限定の返信は元の参加者を維持し、「連合なし」も引き継ぐ。返信に入力したメンションで宛先を増やさない。

添付は16個まで、1ファイル16 MiBまでとする。送り先のサーバー設定・ロール・ドライブ容量による制限が小さい場合は、そちらを優先する。送信前にアップロードしたファイルは、返信を取りやめてもドライブに残る。アップロードの応答を受け取れず再試行した場合も、先に保存されたファイルが残ることがある。返信そのものは送信 ID で重複を防ぐ。

## 表示と登録案内

限定投稿の本文は通常の MFM レンダラーで表示する。CW と投票項目は簡易 MFM と絵文字に対応する。投稿者のホストと投稿元が返す絵文字 URL を使い、同じ名前の絵文字をぐりすぺの絵文字に置き換えない。本文中のホスト省略メンションも投稿者のサーバーを参照する。リアクション件数には保存前のバッファも反映する。

新規登録後の初期設定に、連携先のアカウントを持つ人向けの案内を表示する。案内にはフォローを一度だけコピーすることと、その後のフォロー・解除は独立することを明記する。連携は任意で、設定から後で始められる。

案内から連携画面へ進んでも初期設定を完了扱いにしない。OAuth の完了・中止や再読み込みの後も、「初期設定の続きへ戻る」からプロフィール設定を再開できる。連携機能を無効にしたサーバーや、連携済みのアカウントには案内を表示しない。

## API と権限

| API | 用途 |
| --- | --- |
| `gridspace/private-grant` の `withActions` / `canInteract` | 追加許可の取得と状態確認 |
| `gridspace/private-action` | 操作するアカウントと最新状態の取得、リアクション設定・取消、投票 |
| `gridspace/private-upload` | multipart で受け取ったファイルを旧アカウントのドライブへ保存 |
| `gridspace/private-reply` の `fileIds` / `canAttach` | 旧側に保存したファイルを添付して返信 |

追加スコープは `write:gridspace-actions`。ファイルを添付して返信する場合は `write:gridspace-reply` も必要になる。操作・アップロード API はログインセッション専用で、サーバー間の資格情報を利用者から受け取らない。サーバー間通信は設定した一つの相手への署名付き通信に限定する。応答には `Cache-Control: no-store` を付ける。

表示先でのブロック・ミュートと、投稿元での閲覧権限を確認してから操作する。投稿元では書き込み直前にもトークン、連携世代、投稿の閲覧権限を確認する。アップロードとローカルでの認可解除は直列に処理し、保存中に閲覧権限を失った場合は、その要求が新規作成したファイルだけを削除する。

投票は通常の `notes/polls/vote` と共通の処理を使い、DB のロックで同じ票の二重登録を防ぐ。旧名義で同じ選択肢を再送しても票を増やさない。通常の API は投票済みの場合に従来のエラーを返す。外部サーバーへの配送は通常の ActivityPub 処理を通し、「連合なし」の制約を維持する。

DB の列追加はない。認可セッションの目的を二つ追加するが、既存の文字列列に収まる。両サーバーを更新し、既存利用者は追加の OAuth 許可を行う。
