# 通知の既読と再認可の修正

2026-11-12、総合レビューで残った通知の既読処理、古い連携解除と再認可の競合、タブへ戻ったときの一覧表示を修正した。

## 変更内容

通知ページに「両サーバーの通知をすべて既読にする」を追加した。表示から除外された通知や、投稿削除により表示できなくなった通知も、この明示操作で既読にできる。通常の取得とスクロールでは、引き続き画面内に入った通知だけを既読にする。全件既読の処理後に届いた通知は未読のまま残す。

既読状態が変わらなかった場合は、既読イベントと全件既読のプッシュ送信を繰り返さない。全件既読の指示が自動の既読処理と重なった場合は、先の処理が終わってから実行する。

既読更新の通信失敗では一覧を残し、画面に失敗を表示して再試行する。閲覧権限の失効が分かった場合は、連携先の本文を消す。最初の連携状態の確認に失敗した場合はエラーと再試行を表示し、通常の通知 API が持つ自動既読処理へ切り替えない。未読件数の更新待ちでは前回の件数を残す。

ページ取得と全件既読の応答順が入れ替わっても、古い応答で未読表示を戻さない。取得中に全件既読が完了した場合は同じページを取り直す。全件既読の応答待ちに新たな行を取得した場合は、その行の状態を受信元で確認する。後から来た通知まで推測で既読にはしない。

旧連携の解除通知を再受信しても、既に解除済みなら削除処理を繰り返さない。新しい相手との連携に使うトークンや、進行中の認可セッションを消す問題を修正した。

プロフィール・検索ではタブへ戻った際の認可確認や限定投稿の再取得を待つ間も、通常の投稿を表示し続ける。非表示中に破棄した限定投稿は、再取得してから一覧へ戻す。

## API と配備

`gridspace/notifications/read` に `all: true` を追加した。従来の `ids` による指定も使える。どちらも指定しない場合は `INVALID_PARAM` を返す。全件既読のサーバー間通信は `/gridspace/v1/notifications/read-all` を使う。

連携先の既読更新は既存の通知用の追加認可と書き込み権限を必要とする。更新直前にも認可をロックして確認し、失効していたら書き込みを拒否する。通常の Misskey API の入出力は変えていない。

両フォークを同時に更新する。DB スキーマと migration の変更はない。試験用の G/R サーバーへ反映し、本番環境は変更していない。

## 検証

実サーバーの回帰試験では修正前に「古い解除通知で新しいトークンが消える」不具合を再現し、修正後は新しい連携、トークン、進行中の認可、通知の取得が維持されることを確認した。

通知の実 API 試験では、両側85件ずつのページ送り、表示分だけの既読、明示した全件既読、処理後の新着、片側の操作で他方の85件が未読のまま残ることを確認した。失効した認可と権限不足のトークンでは全件既読を拒否する。

Redis の実処理でも、最初の既読更新だけが変更を返し、二重更新や存在しない ID の指定では変更を返さないことを確認した。64bit の通知順序と、新着後の全件既読も検査した。

ログは各作業環境の `.config/notification-*.log` に保存した。実 API の最終結果は `notification-api-test-verified.log`、ブラウザーの最終結果は `notification-ui-acceptance.log`。試験用の認証情報はコミットしない。
